# Spec: 空间监控与扩大清理范围 v1

## 原始输入

原话全量在 epic 的 [raw-input.md](../raw-input.md)；本 feature 依据 RAW-01、RAW-06、RAW-07。讨论过程：决策卡 https://claude.ai/artifact/B2QaPqf6Fc41G2LptKy1ez。

## 意图

用户不用打开面板，也该知道空间够不够：菜单栏图标旁直接显示剩余空间，按颜色提醒（RAW-07）。监控和清理扩大到开发中常见的占用：Xcode 的设备支持文件和归档、废纸篓、下载文件夹里的大安装包；Docker、OrbStack 只显示大小并提醒（RAW-06）。会丢东西的仍进「待确认」，用户勾选后才做。

## 非目标

- 不替用户删 Docker、OrbStack 的镜像。
- 不扫描下载文件夹里的安装包以外的文件。
- 不改 macOS 的隐私设置：读不到废纸篓时只说明，不绕过。

## 验收标准

| ID | 级 | Given | When | Then | 落点 | 状态 | 证据 |
|---|---|---|---|---|---|---|---|
| AC-01 | [核] | App 在菜单栏 | 平时 | 图标旁显示内置盘剩余空间（如「21G」）；低于提醒线变橙色，低于危险线变红色；每 15 秒更新 | mac原生 | ⬜ |  |
| AC-02 | [核] | 下载文件夹里有 7 天没动、超过 200 MB 的安装包（dmg、pkg、xip、iso），且没有挂载、没在用 | 后台检查 | 进「待确认」，写明大小和「会失去：安装包文件，要用时得重新下载」；勾选后才删 | CLI后端、mac原生 | ⬜ |  |
| AC-03 | [核] | 废纸篓超过 1 GB 且能读到大小 | 后台检查 | 进「待确认」，项目叫「清空废纸篓」；读不到大小时只在体检页说明原因，不进待确认 | CLI后端 | ⬜ |  |
| AC-04 | [核] | Xcode 的设备支持文件 30 天没用、归档是 90 天前的 | 后台检查 | 进「待确认」；归档写明会失去这个版本的安装包和查崩溃用的符号文件 | CLI后端 | ⬜ |  |
| AC-05 | [核] | 装了 Docker 或 OrbStack | 体检 | 显示它们的磁盘镜像大小和「请到 Docker 里清理」，工具不删 | CLI后端、mac原生 | ⬜ |  |
| AC-06 | [边] | 新增的几类进了待确认 | 发通知 | 计入「有 N 项清理等你确认」，沿用每天最多一次的节流 | CLI后端 | ⬜ |  |
