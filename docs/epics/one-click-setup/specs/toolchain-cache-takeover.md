# Spec: 接管开发工具缓存 v1

## 原始输入

原话全量在 epic 的 [raw-input.md](../raw-input.md)；本 feature 依据 RAW-01、RAW-04、RAW-08。讨论过程：决策卡 https://claude.ai/artifact/B2QaPqf6Fc41G2LptKy1ez。

## 意图

各开发工具的下载缓存、编译缓存散在主目录各处，全占着内置盘；Xcode 编译缓存默认没开（RAW-01）。打开「共享构建缓存」后：工具找出本机装了哪些开发工具，插着外接盘时把它们的缓存搬到外接盘上一个由看板管理的目录，原位置留链接，各工具照常使用；同时全局打开 Xcode 编译缓存，同一个任务里切分支、清空重编时更快（RAW-04、RAW-08）。改过的设置随时一键还原。

## 非目标

- 不承诺多个任务共用 Xcode 编译结果（决策卡 R02 实测换目录几乎用不上）。
- 不改项目自己的构建脚本和配置。
- pnpm 包仓库、uv 缓存不搬到外接盘：它们要和项目在同一块盘上才能共享文件。
- 还原时不把缓存搬回内置盘：缓存能重新下载和生成。

## 验收标准

| ID | 级 | Given | When | Then | 落点 | 状态 | 证据 |
|---|---|---|---|---|---|---|---|
| AC-01 | [核] | 打开缓存共享，插着外接盘 | 下一轮后台检查 | 本机装了的工具（Xcode 构建缓存、CocoaPods、Flutter、npm、yarn、Go、Gradle、Cargo、Homebrew、pip）的缓存搬到外接盘上看板管理的目录，原位置留链接；工具照常可用；看板列出每个工具在哪、多大 | CLI后端、mac原生 | ⬜ |  |
| AC-02 | [核] | 某个工具正在运行（例如 Xcode、xcodebuild、go build、pod install） | 轮到搬它的缓存 | 这一轮跳过它，下一轮再试；搬迁过程中文件有变化就放弃，原缓存不动 | CLI后端 | ⬜ |  |
| AC-03 | [边] | 缓存位置已是用户自己做的链接，或工具已改过缓存位置 | 接管 | 在外接盘上的认作已接管，不重复搬、不改用户的设置；还原时也不动它们 | CLI后端 | ⬜ |  |
| AC-04 | [边] | 有 pnpm 包仓库或 uv 缓存 | 接管 | 不搬，写明原因「要和项目在同一块盘上才能共享文件」 | CLI后端 | ⬜ |  |
| AC-05 | [核] | 打开 Xcode 编译缓存 | 之后在新开的终端或 Xcode 里构建 | 自动带上编译缓存设置，同一任务清空重编时用上缓存；用户已有自己的全局 Xcode 设置文件时不覆盖，提示冲突 | CLI后端 | ⬜ |  |
| AC-06 | [核] | 已经接管 | 在看板点「还原」 | 去掉看板做的链接，各工具回到默认位置（缓存从空开始重建），删掉外接盘上的缓存副本，关掉 Xcode 编译缓存；之后新开的终端和 Xcode 不再带编译缓存设置 | CLI后端、mac原生 | ⬜ |  |
| AC-07 | [边] | 没插外接盘 | 打开缓存共享 | 缓存留在原地，只统一显示和清理；Xcode 编译缓存照常打开 | CLI后端 | ⬜ |  |
