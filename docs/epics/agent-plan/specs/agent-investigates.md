# Spec: 告急时先查清为什么 v1

## 原始输入

原话全量在 epic 的 [raw-input.md](../raw-input.md)；本 feature 依据 RAW-40～43。

## 意图

用户问：「资源管理的agent毕竟是agent，为啥没意识到本地的问题」（RAW-43）。

11-03 一台 Mac 的内存「警告」了一整天，swap 从 8 GB 涨到 16 GB。资源看板三次叫起 agent（02:07、08:07、14:42），三次的总结都是「没有新增能处理的，内存仍警告」。占满 CPU 的两路截屏流、几套同时在跑的服务和测试，它一次都没提。后来是用户和另一个 agent 自己查出来的（RAW-40）。

这是告急流程本身的问题，换哪台 Mac 都一样（RAW-41）：
- **内存告急时，材料里没有「谁在占」**：只有压力等级和 swap 用量，进程只列了「父进程已退出、放了一天」的残留后台；
- **步骤是一张为磁盘写的选择题**：关残留后台、挪任务、列给用户、记教训、收尾。内存的问题不在选项里，agent 就照单走完；
- **agent 只看资源看板给的东西**，没有自己去看一眼是谁在占；
- **没解决也不升级**：连续三次「告急尚未解除」，下一次照样走同一张清单；
- **回执是糊的**：agent 交回的决定后台收没收到、做没做，agent 和用户都看不到；
- **「恢复」靠一次采样**：一分钟正常就说恢复了，下一分钟又回到「警告」。

所以 agent 来了先回答「这台 Mac 为什么紧」，证据不够就自己查；查到了能处理；没解决就说清还差什么、要用户做什么。

## 非目标

- 不让 agent 自己杀进程：它只记下决定，真正的动作照旧由后台复核安全底线后做。
- 不放宽安全底线：App 本身、数据库、容器、调试器、模拟器本身照旧不碰；会丢东西的照旧要用户点头。
- 不增加叫 agent 的次数：冷却期和每天的次数不变。

| AC-03 | [核] | agent 查到某个进程该关 | agent 记下决定 | 两种：<br>• [看清是谁](know-who.md) AC-03 允许关的陪跑后台（主人走了或 6 小时没动），和原来没人管的残留后台 → 记成「关掉」，后台复核后关；<br>• 其余的（主人还在） → 列进「等你确认」：写它是谁的、哪个项目、占多少、为什么该关。用户点头后，后台复核还是同一个进程、不是 App 本身、数据库、容器、调试器、模拟器本身，再关 | CLI后端、mac原生 | ✅ | auto: 同上（能关的记成关掉，主人还在的只能列、App 本身和数据库不能列）、test_emergency.ProcessStopTest（用户点头后真进程被关；进程号换了程序就跳过）。实测：agent 看到两路截屏流主人还在、可能用于输入，判断不列 |

| AC-05 | [核] | agent 上一次处理完，同一个原因还没解除 | 又叫 agent | 提示里写「这是连续第 N 次，上次处理完还紧」，要它先说上次漏了什么。连续 2 次没解除，资源看板发一条通知给用户：agent 处理了几次还紧、它说要用户做什么 | CLI后端 | ✅ | auto: 同上（第二次的提示开头是上次的回执和「这是连续第 2 次」，通知标题「agent 处理了 2 次还没缓过来」）。实测：这次记下了「还紧」，下一次因内存叫 agent 时就是第 2 次 |
