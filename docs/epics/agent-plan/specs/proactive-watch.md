# Spec: 主动盯着 v1

## 原始输入

原话全量在 epic 的 [raw-input.md](../raw-input.md)；本 feature 依据 RAW-35～37，以及引出它的 RAW-33。

## 意图

用户的原话是「我还是没感觉到我们这个资源管理agent的主动性和资源管理的agentic能力」（RAW-35）。

10-31 晚，另一个会话同时跑了 4 个 TypeScript 类型检查，每个占 4 GB，整台 Mac 卡死。资源看板这时：
- **没提前打招呼**：内存从 18:34 就开始变紧，一直没发提醒；
- **没自己动手**：每分钟的内存守护因为查进程超时，干脆什么都没做；
- **告急来得太晚，还被拖垮**：等到内存「严重」才叫 agent，agent 又被慢 git 拖崩；
- **一直在等人点头**：那 4 个检查本可以让它们排队一个个跑，等用户回复「暂停排队」时，它们已经跑完了（RAW-36）。

所以资源看板自己每分钟盯一次，内存刚开始变紧就动手（RAW-37）：
- **看趋势**：不等到「严重」，swap 在涨、压力持续偏高就算变紧。
- **明摆着安全的直接做，事后说**：
  - 没人管的残留后台直接关掉；
  - 几件重活同时把内存挤爆时，让它们排队一个个跑。

  什么都不删，排队的随时能恢复。
- **提前提醒，说清是谁**：做了什么，现在谁最占内存；Claude、Codex 会话太大的，提醒开新会话。
- **自己处理完还紧，才叫 agent**：agent 只做要判断的事。
- **看得到它在干活**：封面上写着它最近一次出手做了什么。

## 非目标

- 不删任何东西；删东西照旧要用户点头。
- 不碰数据库、容器、调试器、模拟器，也不碰 App 本身（Claude、Codex、浏览器这些）。
- 不杀重活，只让它们排队：暂停后一定会放行。
- 不做「一键释放内存」：不 purge、不删 swap。

## 验收标准

| ID | 级 | Given | When | Then | 落点 | 状态 | 证据 |
|---|---|---|---|---|---|---|---|
| AC-01 | [核] | 资源看板装好、没关掉这个功能 | 每分钟 | 记下内存压力、swap、内置盘剩余（最近 60 分钟）。出现下面任一情况就算**变紧**：<br>• 压力「严重」；<br>• 「警告」连续 3 分钟；<br>• swap 用到总量的 60% 以上，并且 10 分钟里涨了 2 GB 以上 | CLI后端 | ⬜ | |
| AC-02 | [核] | 变紧 | 同一分钟 | 直接关掉没人管的残留后台，事后告诉用户。条件：父进程已经退出、不是 launchd 管着的服务、开了 24 小时以上，并且属于下面一种：<br>• 截屏流、日志流；<br>• agent 留下的帮手（app-server、MCP 服务、REPL、tail、搜索），而且上一分钟到这一分钟几乎没用 CPU。<br>关之前复核还是同一个进程；数据库、容器、调试器、App 本身一律不碰 | CLI后端 | ⬜ | |
| AC-03 | [核] | 变紧，同时有 2 个以上重活（类型检查、编译、打包、测试，每个占 1 GB 以上） | 同一分钟 | 留下 CPU 用得最多的那个，其余先暂停。之后一次只放行一个：<br>• 正在跑的那个跑完，就放行下一个；<br>• 内存回到正常满 2 分钟，全部放行；<br>• 暂停满 20 分钟，放行它；<br>• 它的上级进程没了，放行它；<br>• 关掉这个功能，全部放行 | CLI后端 | ⬜ | |
| AC-04 | [核] | 变紧 | 一次变紧只发一次 | 发一条通知，写明三件事：<br>• 这次做了什么；<br>• 现在最占内存的前三个，按 App 或程序算；<br>• 最近 3 小时在写、超过 300 MB 的 Claude 或 Codex 会话，提醒开新会话。<br>点开是内存页 | CLI后端、mac原生 | ⬜ | |
| AC-05 | [核] | 自己处理完仍然紧 | 「警告」持续 15 分钟，或「严重」 | 按告急规则叫 agent。agent 上一轮跑崩了、或没跑起来，不算进 6 小时冷却期，也不算进当天次数 | CLI后端 | ⬜ | |
| AC-06 | [核] | 最近 2 小时它动过手 | 用户看封面 | 圆环下面一行写着它做了什么，比如「19:58 让 3 个重活排队 ›」，点开是内存页。agent 正在处理告急时，这一行先显示 agent | mac原生 | ⬜ | |
| AC-07 | [边] | 用户不想要 | `watch off` / `watch on` / `watch status` | 关掉时马上放行所有排队的重活；`status` 说清现在紧不紧、在排队的有哪些、最近做了什么 | CLI后端 | ⬜ | |
