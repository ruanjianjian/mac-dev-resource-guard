# 1.6.1 安全自动维护：验证与安装记录

日期：2026-10-29。平台：Apple Silicon Mac，Xcode 27.0（27A266a）。人类尚未逐项验收；以下为 agent 实测与自动回归结果。所有安装和 CLI 检查均在后台完成，未打开面板。

真实容量与首次命中结果来自先行安全补丁，随后在正式 1.6.1 复验安装、运行时代码、后台入口及缓存重编。未为了证明“好用”制造大缓存再删除，也未重复清理同一对象。

## 可复现步骤

1. 按 [README 安装与升级](../../README.md#自己装) 安装。新用户先确认共享缓存会为新进程设置 Xcode 全局编译配置；现有终端/IDE不会被重启。
2. 按 README 的后台命令体检、关闭外接盘、开启 caches,clean；读回设置、`launchctl getenv XCODE_XCCONFIG_FILE` 和 `resource-guard-service plan --json`。计划是估计，操作前仍需复核。
3. 在单独的本机测试工作树创建 31 个 C 编译单元的 macOS 命令行 target。通过既有 `dev-storage xcode --worktree <测试仓库> --platform macos --configuration Debug -- xcodebuild ... clean build` 连续构建两次，同一工作树和配置使用同一稳定槽，不额外传 derivedDataPath。
4. 检查日志 `CompilationCacheMetrics`，分开记录首次与第二次命中数；运行生成程序。本结果不保证不同工作树、不同源码或不同工具链的命中率。
5. 查看 `~/.local/state/dev-resource-guard/automatic-storage.json` 和安全计划；只将 `deleted[].directory_accounting_bytes` 作为目录计量，另报 observed_free_delta_bytes。没有安全候选时允许结果为 0。
6. 验证安装包 `--self-test`、`codesign --verify --deep --strict`；只读检查运行进程窗口数。不将这些检查冒称为前台界面验收。
